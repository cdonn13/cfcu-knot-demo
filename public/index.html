    Hi, I’m Charlie.

    It’s important for Solutions Engineers to understand the product, so I built a live integration to illustrate a real customer use case.

    The product

    Charlie Federal Credit Union is a stand-in for your customer’s app. Their member taps Update card, signs in to the merchant inside Knot Link — credentials never touch the issuer — and the new card is on file everywhere. Top-of-wallet, kept.

    The integration

    1. 1POST /session/create — the backend creates a Knot session with Basic auth server/knot/client.js
    2. 2knotapi.open({ sessionId }) — the frontend opens the Link SDK public/app.js
    3. 3/webhooks/knot — verify the Knot-Signature HMAC, answer AUTHENTICATED with POST /card inside the 15-second window server/index.js

    That’s the entire surface — one endpoint, one SDK call, one webhook handler. This demo runs on a mock that mirrors Knot’s published API shapes and signs real webhooks; KNOT_MODE=live is the only change to run it against development.knotapi.com.
